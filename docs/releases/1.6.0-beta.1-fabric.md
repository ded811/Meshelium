**Five fixes, and Meshelium now runs on NeoForge as well.**

If you are already running Meshelium on Fabric, this is an update worth
taking: one of the fixes below meant the mod did nothing at all for some
people, silently, and another one could switch it off permanently without
telling you.

Nothing about how the renderer works has changed. Same settings, same
speed, same hardware requirements.

---

## Fixed: Meshelium did nothing at all if you skipped the main menu

If you launch straight into a world — quick play, or your launcher's
"resume last world" button — Meshelium never switched itself on. Not
slowly, not partly: it sat idle for the entire session, with nothing in
the log to say why.

It was waiting for the title screen before checking whether your computer
could run it, and if you never saw a title screen, it never checked. It
now checks the moment your graphics card is ready, whether or not you pass
through the menu.

**If you have ever wondered why the mod seemed to do nothing sometimes,
this was very likely it.**

## Fixed: the "switch to Vulkan" offer could disappear for good

Meshelium only works on Minecraft's Vulkan renderer, so when it finds you
on OpenGL it offers to switch you over. Pressing **Enable Vulkan** counted
as pressing **Don't Show This Again**.

That only bites when the Vulkan startup then fails — but when it does, it
is unrecoverable without knowing where the setting lives. Minecraft
responds to a crash during startup by quietly putting your renderer back
to OpenGL, so the next launch had Meshelium switched off, the offer
already spent, and no message of any kind. The mod stayed dormant forever
on hardware that runs it perfectly well.

Only **Don't Show This Again** retires that message now. If you think this
happened to you, Meshelium Settings → Advanced → Backend Popup turns it
back on.

## Fixed: three ways terrain could go missing

- **A squared-off bite of missing ground and water** at the edge of the
  loaded area, on the side you were moving away from. Minecraft lists
  chunks for drawing in a circle but keeps them in memory in a square, so
  a chunk that slips out of the circle is still loaded, still fully built,
  and drawn by nobody. Meshelium draws that terrain itself now, since the
  game has already paid to build it. It was about five chunks deep at
  render distance 16, and it took the water surface with the land over an
  ocean.
- **The ground and the ocean below you emptying out** when you fly upward.
- **Water and glass vanishing** while the land beside them stayed.

## Also: Meshelium runs on NeoForge

There is now a NeoForge build, released separately as a beta. It is the
same mod — both loaders are built from one shared set of code and differ
only in the few lines each needs to start up.

Nothing changes for you on Fabric. If you move to NeoForge, take the
NeoForge file instead of this one; they are not interchangeable.

---

## What you need

Unchanged from 1.5:

- **Minecraft 26.2** with the **Fabric** loader (0.19.0 or newer)
- **Fabric API**
- **Minecraft's Vulkan renderer**: Options → Video Settings → Graphics API
  → Vulkan, then restart. Meshelium offers to switch it for you.
- A graphics card with mesh shaders: **AMD** RX 6000 or newer, **NVIDIA**
  GTX 16xx or newer, or **Intel** Arc. Laptop and handheld chips count,
  including the Steam Deck.
- **Windows or Linux.** No macOS — Macs do not do mesh shaders on Vulkan.

Client-side only. Your friends do not need it and neither does your
server. **Bobby** is still worth having on multiplayer, so there is
something for Meshelium to draw past the server's view distance.

If your card cannot do mesh shaders, Meshelium switches itself off, tells
you why, and your game carries on normally.

---

## Why this is a beta

The renderer is the same code that has been in the Fabric releases, and
the fixes above are verified: the full client test suite runs a real
client on a real GPU and leaves screenshots that get looked at, on both
the Vulkan and the OpenGL path, and the mod reports nothing still
allocated when the game shuts down.

What makes it a beta is company rather than doubt — it goes out alongside
the first NeoForge build, which has only been run on one machine. Holding
both at beta for a cycle keeps the pair honest.

Tested on an AMD RX 9070 XT on Windows 11. If something goes wrong the log
is worth attaching; Meshelium writes down what it decided and why at
startup.
